# 호토리 · HOTORI

호텔 토탈 리포트 · 곁에 있는 운영 파트너

## 프로젝트 이름

- 한글 이름: **호토리**
- 영문 이름: **HOTORI**
- 개발 식별자: `hotori`
- 브랜드 표현: **ホテル トータル レポート**
- 브랜드 방향: 복잡한 호텔 업무를 기억하고 항상 운영자 곁에 머무는 소프트웨어.
- 사용 문장: “호토리에 예약 기록해 줘.”

사용자가 제시한 브랜드 스토리는 일본어 `ほとり`의 ‘곁, 주변’이라는 이미지와 연결합니다. 이 문장은 이름의 이야기이며 음성 예약 기능이 구현되었다는 의미는 아닙니다.

호텔의 예약·객실·매출·인수인계를 관리하는 **호토리의 작동하는 로컬 초안과 개발 기획**입니다. PC·Android·iOS를 지원하는 부분 유료화 서비스로 확장하는 것을 목표로 합니다.

현재 상태: **작동하는 로컬 초안 0.1.0**. 작성일: 2026-10-17, Asia/Seoul.

## 바로 실행

Node.js와 npm이 설치된 환경에서 프로젝트 폴더를 열고 실행합니다.

```powershell
npm install
npm run dev
```

브라우저에서 [호토리 로컬 초안](http://127.0.0.1:5173)을 엽니다. 서버 종료는 실행 중인 터미널에서 Ctrl+C입니다.

빌드한 화면을 확인하려면 개발 서버를 종료한 뒤 실행합니다.

```powershell
npm run build
npm start
```

이때 주소는 [http://127.0.0.1:3100](http://127.0.0.1:3100)입니다. 두 실행 방식을 동시에 사용하지 않습니다.

## 휴대폰 확인용 배포 (Render 무료)

저장소의 `render.yaml`로 Render 무료 웹 서비스에 올려 휴대폰에서 확인할 수 있습니다. 환경 변수를 넣지 않으면 위의 로컬 실행 방식은 그대로입니다.

1. GitHub 저장소를 Render의 **New → Blueprint**로 연결합니다.
2. 처음 만들 때 `HOTORI_ACCESS_PASSWORD`에 접속 비밀번호를 입력합니다. 영문·숫자 위주로 길게 정하고 저장소에는 적지 않습니다.
3. 배포 후 `https://<서비스이름>.onrender.com`을 열면 브라우저가 아이디·비밀번호를 묻습니다. 아이디는 아무 값이나 되고 비밀번호만 확인합니다.

| 환경 변수 | 설명 |
| --- | --- |
| `HOTORI_ACCESS_PASSWORD` | 설정하면 화면과 모든 API에 비밀번호(HTTP Basic 인증)가 걸립니다. `/api/health`만 예외입니다. |
| `HOST` | 기본 `127.0.0.1`. Render에서는 `0.0.0.0`. 외부 주소인데 비밀번호가 없으면 서버가 시작을 거부합니다. |
| `PORT` | 기본 `3100`. Render가 자동으로 넣습니다. |
| `HOTORI_ALLOWED_HOSTS` | 추가로 허용할 접속 주소(쉼표 구분). Render 기본 주소(`RENDER_EXTERNAL_HOSTNAME`)는 자동 허용됩니다. |

주의: 무료 서비스는 15분 동안 접속이 없으면 잠들고, 다시 열 때 1분쯤 걸립니다. 디스크가 임시라서 재배포·재시작·잠들기 때마다 데이터가 가상 데모 데이터로 초기화됩니다. 공개 저장소이므로 실제 고객 정보는 입력하지 않습니다. 비밀번호를 아는 사람은 누구나 모든 기능(플랜 체험 전환 포함)을 쓸 수 있습니다.

## 이번 초안에서 확인할 수 있는 것

- 운영 현황, 예약 관리, 객실 관리, 매출 리포트, 팀 관리, 호텔 설정의 6개 화면.
- 예약 등록·변경·취소, 객실 배정·입실·퇴실과 서버의 숙박일별 재고 검사.
- 객실 등록, 청소·시설 상태 변경, 객실별 인수인계 접수·처리·해결과 이력 보존.
- 숙박일 기준 판매금·수수료·예상 정산액, 가상 구성원 등록·출퇴근 기록, 무료·프로 제한 체험.
- 내장 PostgreSQL(PGlite) 저장. 변경 내용은 `.hotori-data/postgres`에 보관되어 새로고침과 서버 재시작 후에도 유지됩니다.

**이 PC의 단일 호텔을 신뢰하는 운영자가 사용하는 로컬 데모**입니다. 가상 호텔 16실과 예약 12건으로 시작하며 실제 고객 정보는 입력하지 않습니다. 플랜 전환은 결제 없는 체험입니다. 실제 인증·직원 초대와 접근 권한, 유료 결제, 다른 기기 간 공유, Android·iOS 설치형 앱은 별도 구현·검수가 필요합니다. 현재 화면은 반응형 웹 초안입니다.

최종 코드 수정 후 `npm test` 14개와 `npm run build`가 통과했습니다. 브라우저에서 예약 생성·변경·취소·새로고침 보존, 무료·프로 전환, 기간 리포트와 모바일 화면을 확인했습니다. 상세 수행 범위는 아래 검수 기록에 남겼습니다. 상용 운영이나 앱스토어 출시를 완료했다는 의미는 아닙니다.

- [초안 실행 안내](docs/HOTORI-초안-실행안내.md): 실행·저장 방식, 구현 범위와 제한.
- [초안 검수 기록](docs/HOTORI-초안-검수.md): 업무 규칙, 저장·동시성 검수 결과.
- [개발 인수인계서·그록봇 검토 요청](docs/HOTORI-개발-인수인계서-그록봇.md): 현재 구현과 목표 설계의 차이, 코드 구조, 미완료 범위, 다음 개발 검토 질문.
