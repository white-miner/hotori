# 호토리 · HOTORI — 예약 장부 (v3)

여러 플랫폼(야놀자·여기어때·아고다·부킹닷컴·현장…)에서 들어온 예약을 **사람이 직접 빠르게 적는 장부**예요.
목표는 두 가지: **오버부킹 막기**와 **미판매(공실) 막기**. 날짜별·타입별 남은 객실을 크게 보여 주고, 직원은 그 숫자를 보고 메인 플랫폼 재고를 직접 조정해요.

- 청소 상태, 체크인·퇴실 처리, 외부 플랫폼 연동·자동화는 **넣지 않아요** (호텔 PMS가 하는 일).
- 설계안: [`docs/HOTORI-설계안-v3-장부.md`](docs/HOTORI-설계안-v3-장부.md)

## 화면
| 화면 | 하는 일 |
|---|---|
| 현황판 | 위쪽 탭 두 개: **재고 현황**(14일 남은 객실 표: 여유 / 적음 / 0 만실 / −1 초과, 날짜를 누르면 그날 객실 배치로) · **객실 배치**(선택한 날 밤의 방 번호 보드, 건물이 2개 이상이면 전체·건물별 탭과 건물 제목 + 대실 목록 + 방을 안 정한 숙박). 기기마다 마지막 탭을 기억하고 주소는 #/board/stock · #/board/rooms. 오버부킹이 있으면 두 탭 모두 맨 위에 빨간 알림 |
| 예약 기록 | N 키로 열기. 숙박/대실, 플랫폼(1~9), 타입(Q W E R T…), 입실 날짜, 박수(←→), 이름·총액, 방(선택), ◯ 입실, 메모. 저장 전 "S 남은 객실 4 → 3" 미리보기 |
| 장부 | 목록·검색(/ 키)·기간·플랫폼·타입·종류·취소 필터 |
| 설정 | 건물(본관·별관·A동… 추가·이름·순서·삭제), 층(번호줄 색), 방 번호(601~610처럼 한 번에), 방별 색(특수객실), 객실 타입(약자 최대 12글자+이름), 플랫폼(한 글자 약자), '적음' 기준, 요금제 표시 |

## 계산 규칙 (`shared/ledger.ts`, 테스트 `shared/ledger.test.ts`)
- 남은 객실(타입, 날짜) = 그 타입 방 수 − 그날 밤을 차지한 숙박 수
- N박 = 입실일부터 N개의 밤. **퇴실하는 날 밤은 비어요.**
- 방을 정했으면 **실제 방의 타입**에서, 안 정했으면 판 타입에서 빠져요.
- 대실은 계산에 넣지 않아요 (이용시간 12:00~14:00 필수).
- 취소·노쇼는 줄을 그어 남기고 재고를 돌려줘요. 그 자리를 새 예약이 채우면 보드에서 사라지고 장부에만 남아요.
- 영업일: 새벽 6시 전(서울 시간)은 전날로 봐요 (`BUSINESS_DAY_CUTOFF_HOUR = 6`).
- 판매가격은 총액으로 적고 1박 평균은 자동 계산해요.
- 건물: 호텔 → 건물 → 층 → 방. 방은 id로 구분해서 건물이 다르면 같은 번호(본관 201 · 별관 201)를 써도 돼요. 겹치는 예약 확인도 방 id 기준이에요. 남은 객실은 건물과 상관없이 타입별 합계예요. 건물이 하나면 화면은 예전과 같아요 (건물 정보가 없던 설정은 '본관' 하나로 읽어요).

## 구조
- 화면: React 19 + TypeScript + Vite. 글꼴(Pretendard, M PLUS Rounded)은 `src/assets/fonts`에 들어 있어요.
- 데이터·로그인: **Supabase** (이메일+비밀번호). 호텔마다 RLS로 자기 데이터만 보여요. 스키마는 `supabase/migrations/`.
  - `hotels`(이름, plan free/pro, 설정 JSON), `hotel_members`, `bookings`
  - 요금제(plan)는 사용자가 바꿀 수 없어요 (컬럼 권한으로 막음)
- 여러 기기 동시 사용: Supabase 실시간 알림 + 10초마다 다시 확인
- 서버: `server/` Express가 빌드된 화면만 보내요. `HOTORI_ACCESS_PASSWORD`가 있으면 공용 비밀번호를 한 번 더 걸고, 없으면 걸지 않아요.

## 실행
```bash
npm install
npm run dev        # http://127.0.0.1:5173 (.env.development의 Supabase를 써요)
npm test           # 계산 규칙 테스트
npm run build && npm start   # http://127.0.0.1:3100
```
Supabase 주소와 **publishable 키**(공개용)는 `.env.production` / `.env.development`에 있어요. 비밀 키(service_role, sb_secret_…)는 절대 넣지 마세요.

## 배포 (Render)
`render.yaml` 참고. 빌드 `npm ci --include=dev && npm run build`, 시작 `node dist-server/index.js`.

## 예시 데이터
`node scripts/demo-seed.mjs <hotel-uuid> [기준날짜]`가 화이트보드와 같은 방 번호(601~610 …)로 예시 예약 SQL을 만들어요. 손님·금액은 모두 예시예요.
