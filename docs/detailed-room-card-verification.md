# HOTORI 상세형 객실카드 구현·검증 기록

검증일: 2026-10-29 (Asia/Seoul). 개발 브랜치: `codex/detailed-room-cards`. 기준 코드: 원격 main `4f4ec23`.

## 기준 정정과 범위

처음 열었던 로컬 체크아웃은 `codex/revert-room-card-frame`으로 최신이 아니었다. 코드 수정 전에 원격 main을 fetch하고 최신 코드를 기준으로 개발 브랜치를 만들었다. 최신 좌측 사이드바와 현황/배치 통합 구조를 유지했다.

`https://hotori.onrender.com`은 열었으며 이 브라우저에서는 로그인 화면까지만 확인했다. 변경 UI 검증은 사용자가 로그인해 준 로컬 `http://127.0.0.1:5173/#/board/now`에서 최신 원격 코드와 실제 Supabase 데이터로 수행했다. 배포 사이트에 이 변경은 아직 배포되지 않았다.

로그인 계정의 실제 등록 구성은 본관 40실, 별관 19실, 총 59실이다. 본관은 7층 1실·6층 9실·5층 10실·3층 10실·2층 10실이며, 별관은 6층 9실·5층 9실·3층 1실이다. 지시서의 41실과 다르므로 임의 객실을 추가하거나 실제 번호를 예시 번호로 교체하지 않았다.

## 실제 화면 검증

- 1920×1080, devicePixelRatio 1, CSS zoom 1에서 59실과 기존 번호·순서를 확인. 8개 층 모두 카드 top 좌표가 한 값으로 층당 한 줄임을 확인.
- 사이드바 레일에서 카드 약 164px, 사이드바 고정 시 약 138px. 본문 16px를 유지하고 좁은 카드의 버튼은 하단 두 줄로 배치. 두 상태 모두 자식 텍스트의 가로 넘침 없음.
- 예약자·실제 타입·예약 경로·입퇴실 예정 시간·열린 숙박·예약 총액·실제 박당 요금·결제 내역 확인. 예약 없는 객실은 예약 없음/빈 값 확인.
- 상세보기 클릭 → 기존 수정하기 화면의 실제 객실·입퇴실·총액·결제 내역 확인 → 닫기 정상.
- 빠른 업무 클릭 → 좌측 사이드바 펼침, 해당 객실의 숙박/대실 판매·청소 요청·결제·이동·수정·퇴실 업무 확인. 우측 패널은 새로 만들지 않음.
- 기존 이용기간 버튼 → 점유 밤 달력 팝오버 → 닫기 정상.
- 본관 6층 색상을 테스트 색상으로 변경 → 9실 번호 배경 즉시 동일하게 반영 → 저장 → 새로고침 후 유지 확인 → 원래 색상으로 복원.
- 실제 4실 단체 선택 → 4실 강조. 단체 객실만 체크 → 실제 단체 9실만 표시. 해제 → 전체 59실 복귀.
- 실제 단체 대표를 602호에서 502호로 변경 → 대표 표시와 연결 표시 갱신. 각 구성원의 입퇴실·플랫폼·객실 금액이 그대로임을 비교. 원래 대표 602호로 복원.
- 실제 단체 색 변경 → 4실 전체에 반영 확인. 원래 단체 색으로 복원. 층 색·상태 색은 유지.

## 격리 UI 검증

운영 예약의 연결을 해제하지 않기 위해, 실제 NowGroupBar/ConfirmHost를 렌더링하고 저장 명령을 메모리 어댑터에 연결한 별도 로컬 검증 화면을 사용했다. 이 화면은 운영 DB 검증을 대신한 것으로 주장하지 않는다.

- 기존 개인 예약을 단체 A에 연결 → 해당 예약의 연결만 변경.
- 단체 A의 대표 예약 연결 해제 → 해당 예약은 개인 예약으로 남고 다른 구성원 및 단체 B 유지.
- 전체 연결 해제 확인창에서 취소 → 연결 유지.
- 확인창에서 해제 확정 → 단체 A의 남은 예약만 개인으로 변경, 단체 B 유지.
- 각 단계에서 객실·가격·결제·입실 여부·체크아웃·기간·박별 요금·메모 스냅샷 동일함을 확인.
- 기존 `moveBookingGroup` 명령에 대한 올바른 대상/인수 호출을 확인. 실제 Supabase 연결 해제 API의 운영 DB 실행 검증은 하지 않음.

## 자동 회귀와 빌드

최종 `npm test`: 800개 통과, 실패 0개. `npm run build`: TypeScript 검사·프런트엔드 빌드·서버 빌드 성공. 함께 제공하는 evidence JSON과 실행 로그에도 결과를 기록했다. 상태 윈도우, 장기·열린 숙박, 결제, 단체 원장, 예약 수정·취소, 재고·중복 배정·객실 이동, 사이드바, 서버 회귀를 포함한다. 기존 코드 순서를 고정하던 테스트는 새 카드의 명시된 항목 순서에 맞춰 갱신했다.

## 남은 검수와 제한

- 신규 예약의 운영 DB 저장/수정/삭제, 실제 체크인·체크아웃, 실제 단체 연결/해제는 실행하지 않았다. 기존 폼의 진입·닫기와 회귀 테스트를 확인했다. 운영 데이터를 변경하는 최종 검수에는 별도의 테스트 계정/예약이 적절하다.
- 현재 날짜의 운영 데이터에 네 상태가 모두 있지는 않아, 대실·미입실·퇴실 시간 경계는 상태/렌더 회귀 테스트로 검증했다.
- 기기별 G 표시번호와 구성원 표시 순서를 모든 직원의 공통 서버 번호로 동기화하는 기능은 없음. 실제 정식 연결 ID는 기존 UUID이므로 데이터 연결에는 영향이 없다.
- 41실이라는 수량 기준은 현재 로그인 계정의 등록 구성과 불일치한다. 현재 데이터를 보존했다.
- 24인치 실물 모니터에서 80cm 거리의 최종 가독성 평가는 사용자 검수가 필요하다. 브라우저의 FHD 해상도·글자 크기·넘침을 검증했다.
- 모바일 전용 개선은 우선 범위가 아님. 더 좁은 PC 화면에서는 가로 스크롤을 허용한다.
- DB 테이블/컬럼/RLS/마이그레이션 변경 없음. 예약 등록·수정·삭제 데이터 함수 변경 없음. 배포·원격 push 없음.
