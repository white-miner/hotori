# 스마트등록 취소·마스킹 이름 보존 검증

검증일: 2026-10-31 KST. 기준 main 7562df0.

## 확인한 사실과 변경

사용자가 제공한 일반 텍스트를 현재 파서에 직접 넣으면 이름은 마스킹 그대로, 상태는 예약취소로 인식됐다. 기존에 잘못 저장된 행의 최초 클립보드 HTML과 당시 원문은 저장돼 있지 않으므로 최초 발생 경로를 단정할 수 없다. 코드 조사에서는 HTML 표가 있으면 일반 텍스트를 무조건 버리는 붙여넣기 경로를 발견했다. 카드 상태가 HTML 표 밖에 있거나 양쪽 이름이 다르면 이 경로로 원문 정보가 유실될 수 있다.

- 카드 형태로 인식되는 일반 텍스트는 HTML 표보다 우선한다. 표 전용 복사/엑셀 HTML 변환은 유지한다. 일반 텍스트의 선택 영역 삽입과 추가 붙여넣기는 브라우저 기본 동작을 사용한다.
- 마스킹된 한글 이름을 이름 후보로 인정하고 별표를 추정·확장하거나 채널명으로 소비하지 않는다.
- 같은 예약 블록의 판매금 뒤 또는 공백이 있는 명시적 예약취소/고객취소/취소완료도 보존한다. 객실명·쿠폰·취소 규정의 부분 문자열로 취소를 추정하지 않는다.
- 미리보기에 붙여넣기 이름과 가져온 상태를 표시한다. 미리보기에서 이름을 수정해도 원문 이름은 별도로 유지한다.
- 새 예약 메모에 가져온 이름·상태를 별도 줄로 보존한다. 기존 스마트등록 라벨·객실 타입·예약번호 메모의 첫 줄 형식은 유지한다.
- 일반 생성 함수로 잘못 진입해도 취소 신호/상태가 있는 원문은 active로 저장되지 않는다. 신규 업로드 대상에서도 취소 원문을 제외한다.
- 기존 예약·이름·금액·결제는 일괄 정정하지 않았다. 이미 저장된 행은 사용자가 직접 수정·삭제한다는 지시를 따랐다. DB 마이그레이션 없음.

## 별도 요청: 방 이동 기획

먼 객실까지 드래그하는 대신 빠른 업무에서 가까운 목적지 선택창을 제공하는 방식을 권장한다. 객실번호 검색, 건물·층·타입 필터, 같은 층/같은 타입 우선 목록, 전체 이동 기간의 이동 가능 여부와 불가 사유를 표시한다. 숙박 전체/선택일부터 퇴실까지를 먼저 선택하고, 출발·도착·적용 기간·타입 변경을 확인하여 실행한다. 맞교환은 숙박 전체에만 적용되는 별도 기능으로 구분한다.

Dashboard의 startOpsRoomMove/mvCellBits/doMove, shared/ledger.ts의 boardMoveTargets/boardMove 및 기존 확인·되돌리기 로직을 재사용할 수 있다. 기존 MoveScheduleSheet는 2박 이상 이동 예약 기능이며 점유 객실 선택을 허용하므로 엄격한 이동 가능 목록과 동일하게 취급하면 안 된다. 현재 맞교환은 순차 저장+실패 복구 방식이다. 새 DB 구조는 필요하지 않다. 이 요청은 기획까지 수행했고 이동 UI 자체는 이번 오류 수정에 섞어 구현하지 않았다.
