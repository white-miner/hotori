# 숙박 요금 입력 단순화 및 1박 총액 저장

검증일: 2026-10-31 KST. 기존 main 24d3ce4 기준. DB 마이그레이션과 기존 예약 일괄 보정은 하지 않았다.

## 변경 사항

- 간단 예약, 숙박 판매, 상세 등록·수정, 다실 객실별 요금에 공통 입력기를 적용했다.
- 매일 같은 요금: 객실별 1박 금액 하나로 선택한 숙박일을 채우고 총액을 계산한다.
- 날짜별 요금: 날짜·요일별 객실료를 한 표에서 입력한다. 누락된 날짜가 있으면 저장을 막는다. 일부 날짜 0원은 유지하고 전체 객실료 0원은 기존 금액미정 규칙을 사용한다.
- 총액에서 균등 계산: 직원이 총액 입력/적용을 선택했을 때만 배분한다. 나머지 원은 마지막 숙박일에 더한다.
- 1박 총액 170,000원은 해당 날짜 nightRates.nights에 170,000원을 함께 저장한다. 시간 비용·객실 추가 항목·할인은 별도 계산하며 수납액/플랫폼 입금액을 객실료로 사용하지 않는다.
- 기존 예약은 입력 방식을 둘러보거나 열고 저장하는 것만으로 요금을 다시 배분하지 않는다. 요금을 수정해도 기존 결제 내역·단체 연결·객실 배정·메모를 유지한다.
- 간단→상세 전환에서도 입력한 날짜별 요금을 전달한다.
- 채널 변경·설정 재조회로 입력 중인 금액을 지우지 않는다. 균일가/총액 방식의 기간 변경은 선택한 방식대로 새 날짜를 계산한다.
- 겹쳐 있던 박당/총액·박별 펼침·박당 채우기·자동 계산·합계 반영 체크박스를 제거했다. 설정 요금은 날짜별 입력의 빈 날짜 채우기 한 곳에서만 명시적으로 적용한다.
- 간단 예약 및 숙박 판매 팝업은 제목·취소/저장 버튼을 고정하고 본문만 스크롤한다. 다실 요금 입력은 카드 전체 너비를 유지한다.

## 실제 UI 검증

운영 DB와 연결하지 않은 하네스에서 실제 SimpleBooking/StaySaleModal/Entry 및 기존 저장계획 함수를 실행했다. 운영 화면은 진입·입력 미리보기·취소만 하고 저장하지 않았다.

- 간단 예약 1박 총액170,000원 저장: price170,000원, 해당 날짜 요금170,000원 확인.
- 실제 객실 카드 렌더 회귀 테스트: 해당 날짜170,000원이 표시되고 요금 미등록 문구가 없음.
- 3박 균일가70,000원: 날짜3개70,000원, 총액210,000원으로 저장.
- 3박 총액200,000원: 66,666/66,666/66,668원으로 합계 일치.
- 날짜별60,000/80,000/90,000원: 총액230,000원 저장.
- 날짜2개 중1개 미입력: 저장 차단과 안내 확인.
- 숙박 판매1박170,000원: 실제 buildStaySaleDrafts에 날짜 요금이 전달되고 예약에 유지됨.
- 같은 타입2실: 첫 객실2박×60,000원=120,000원, 둘째 객실 총액170,000원=85,000/85,000원. 서로 다른 단가·같은 그룹 연결·총액290,000원 확인.
- 기존 예약70,000/80,000원·총액150,000원·카드수납100,000원: 탭만 바꾼 뒤 저장해도 요금·수납·메모·단체 연결 유지.
- 기존 예약 두 번째 날짜만90,000원으로 변경: 총액160,000원, 첫 날짜70,000원과 기존 카드100,000원·메모·단체 연결 유지.
- 현장→플랫폼, 설정 재조회, 박수 변경 이후 입력 유지·선택 방식에 따른 재계산 확인.
- 실제 로컬 운영 화면:3박 균일가70,000원 미리보기 및 상세 전환3날짜 각각70,000원 확인 후 취소. 운영 DB 쓰기 없음.
- 1920×1080 FHD와1063×712에서 팝업 확인. 1063 화면 모달 y16~696, 제목 y42~86, 저장/취소 y630~674. 본문만 스크롤하고 입력기는 가로 넘침 없음.
- 증거 및 테스트 로그: test-results/stay-pricing/ 아래 PNG, test-results/stay-pricing-tests.log, stay-pricing-build.log. 테스트 산출물은 커밋하지 않는다.

## 데이터 영향 및 제한

기존 night_rates JSON 구조와 예약·결제 API를 재사용한다. 기존 DB의 누락된 날짜 요금은 자동 보정하지 않는다. 필요하면 해당 예약에서 총액 입력 후 날짜 요금 적용으로 사용자가 정정한다. 오래된 기록을 배분하는 판단은 이번 변경에 포함하지 않는다. 실제 저장 검증은 운영 데이터 손상을 피하기 위해 메모리 전용 데이터로 수행했다.
