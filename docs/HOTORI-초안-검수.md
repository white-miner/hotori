# HOTORI 초안 검수 기록

검수일: 2026-10-17 (한국 시간)

이 기록은 로컬 초안의 업무 규칙과 데이터 저장 검수 결과다. 실제 호텔 운영 데이터, 실제 사용자 인증, 유료 결제, Android/iOS 앱 패키지의 검수를 의미하지 않는다.

## 실행 결과

- 최종 코드 수정 후 독립 재실행한 `npm test`: 14개 테스트 통과, 실패 0개. `tsx --test server/core.test.ts`로 실행했으며 종료 코드는 0이다.
- 최종 코드 수정 후 독립 재실행한 `npm run build`: TypeScript 검사와 Vite 배포 빌드 통과, 종료 코드 0. Vite 7.3.7에서 1,579개 모듈을 변환했고, 최종 JS는 `dist/assets/index-FG3cucav.js`(275.25 kB), CSS는 `dist/assets/index-IPDd5-Lt.css`(47.62 kB)다.
- 별도 PGlite 인메모리 저장소에 제어 가능한 시계와 임의 요청 ID를 사용한 독립 검수: 아래 10개 묶음 통과.
- 기존 `.hotori-data` 저장소에 독립 검수 데이터를 기록하지 않았다. 재시작 지속성 테스트는 `core.test.ts`에서 OS 임시 디렉터리를 사용한다.

## 독립 검수한 업무 규칙

1. 한국 날짜와 달력 기준 무료 과거·미래 각각 1개월, 프로 각각 6개월을 확인했다. 8월 31일에서 6개월 뒤는 2월 말일로 보정된다. 프로 상한 밖의 과거·미래 예약 등록은 거절된다.
2. 프로에서 오래된 예약, 무료 과거 경계에 걸친 연박, 무료 미래 범위 밖 예약을 생성했다.
3. 무료 전환 후 오래된 예약과 해당 감사 기록이 응답에서 제외된다. 경계 연박은 허용 날짜의 요금만 표시된다. 기존 프로 미래 예약은 남는다.
4. 화면에서 숨긴 과거 예약의 ID와 버전을 직접 보내도 변경·취소·배정이 거절된다. 과거 경계에 걸쳐 일부만 보이는 예약의 내용 변경도 거절된다.
5. 허용 범위 밖 현황·매출 조회와 무료 기간별 매출 조회가 직접 저장소 호출에서도 거절된다. 무료 허용일의 일별 매출 조회는 가능하다.
6. 무료 전환 후 기존 프로 미래 예약의 취소는 가능하다. 제한 범위 밖으로 숙박 기간을 추가 확장하는 변경은 거절된다.
7. 무료 19실 상태에서 서로 다른 객실 추가 요청을 동시에 2개 전송했다. 1개만 저장되고 다른 요청은 `ROOM_LIMIT`으로 거절되어 최종 20실을 유지했다.
8. 한 객실의 미해결 항목은 무료 1개, 프로 30개까지 저장된다. 31번째 실패 요청은 리비전을 올리지 않았다. 무료 전환 후 기존 30개 기록을 보존하며 해결 처리할 수 있다.
9. 중복 출근을 거절한다. 무료 전환 후 기존 출근 기록의 퇴근 처리와 서버 시각 저장이 가능하다. 같은 기록의 중복 퇴근은 거절된다.
10. 존재하지 않는 날짜, 음수 금액, 0개·소수 객실 수, 잘못된 숙박 기간, 짧은 요청 ID를 거절한다. 실패 후 리비전은 변하지 않는다.

## 포함된 자동 회귀 검수

`server/core.test.ts`는 위 일부 규칙 외에도 아래 동작을 검수한다.

- 마지막 1실에 대한 동시 예약 중 1개만 성공한다.
- 실패한 예약 변경은 원본 예약을 보존한다.
- 같은 요청 ID와 내용으로 재시도하면 중복 저장하지 않는다. 다른 내용에 같은 ID를 재사용하면 거절한다.
- 오래된 버전을 사용한 변경을 거절하며, 취소한 재고는 다시 판매할 수 있다.
- 저장소를 닫고 다시 열어도 호텔명, 예약, 리비전, 멱등 처리 결과를 보존한다.
- 날짜별 매출·수수료를 합치면 예약 전체 금액과 일치한다.
- 청소가 끝나지 않은 객실 입실과 겹치는 객실 배정을 막는다. 퇴실 시 청소 필요 상태로 바뀐다.
- 날짜별 잔여 재고만으로는 수용 가능해도 연박 전체를 같은 방에 수용할 수 없는 경우 저장을 거절한다. 객실 이동은 초안 범위에 없다.
- 무료에서 생성한 예약을 프로에서 미래로 연장해도 무료 전환 후 기존 업무 기록을 유지한다.

## 검수 중 수정된 문제

과거 조회 범위를 지난 미퇴실 예약을 보존하는 과정에서 음수 숙박일을 계산하여 전체 현황 조회가 실패하는 경우를 확인했다.

최초 재현식: `snapshot(seed('2026-10-17'), '2026-11-20', '2026-11-20')`

업무 규칙 수정 후 같은 식은 정상 응답한다. 미퇴실 업무 4개는 남고 기간 밖 금액은 0으로 가려진다. 별도 자동 회귀 검수에서도 해당 예약의 퇴실 처리가 가능하며, 퇴실 전에 해당 방의 판매를 중지하는 작업은 거절되는 것을 확인했다.

## 브라우저 검수 — 주 작업 에이전트 수행

아래 항목은 주 작업 에이전트가 실제 브라우저에서 수행해 전달한 결과다. 위의 독립 저장소·자동 테스트 검수와는 수행 주체를 구분한다.

- 95,000원 예약 생성 후 새로고침해 저장 유지, 100,000원으로 변경 후 표시·재고 갱신, 취소 후 재고·매출 복원을 확인했다.
- 0원 예약을 생성한 뒤 다시 조회해 0원이 유지되는 것을 확인했다.
- 모바일 예약 모달의 체크인 날짜를 빈 값으로 설정했다. 모달이 유지되고 날짜 선택 안내와 총액 0원이 표시되었다.
- 프로에서 2개월 뒤 현황을 조회하다 무료 체험으로 전환했다. FREE 상태로 바뀌고 오늘 날짜 현황을 정상 재조회했다.
- 프로의 2026-10-15~2026-10-17 기간 리포트에서 판매금 1,330,000원, 수수료 87,000원, 예상 정산액 1,243,000원을 확인했다.
- 무료에서 이미 미해결 항목 1개가 있는 303호에 항목을 추가했다. 서버의 한도 오류가 표시되고 입력 내용은 유지되었다.
- 390×844 화면에서 본문 폭 390px, 모달 폭 360px이며 가로 넘침이 없는 것을 확인했다.

## 해석과 남은 검수 범위

- 매출은 숙박일별 판매금 기준이다. 실제 결제 입금·환불·세무 정산을 검증한 결과가 아니다.
- 플랜 변경은 무료·프로 동작을 확인하기 위한 로컬 체험 기능이다. 실제 결제 승인이 아니다.
- 동시성·지속성 결과는 단일 서버 프로세스와 내장 PostgreSQL 저장 구조에 해당한다. 다중 서버, 클라우드 장애 복구, 호텔별 데이터 격리 검증은 별도다.
- 실제 계정 초대, 로그인, 직원별 서버 권한, 원격 기기 간 동기화, 결제, 앱스토어 배포, 백업·복구 운영은 향후 구현·검수가 필요하다.
- 브라우저 검수는 위의 실제 수행 경로와 화면 크기에 대한 결과다. 모든 모바일 브라우저·기기 조합을 검수한 것은 아니다.
