# 단체 기간 결제 + 대장 객실 — 계획 (2026-10-27)

## 1. 감사 (audit)
- 대장 객실: 저장 값 없음. `groupLeadBooking()`이 "수납액 최대, 동률이면 목록 첫 방"으로 매번 계산.
  - 스크린샷의 "대장 본관 302호": 4개 방 수납 0원 → 동률 → 목록 첫 예약(302, 10/21 중도퇴실로 빈 방인데 status=active)이 대장. 건물이 여러 개라 라벨이 "본관 302호".
  - 결제가 한 번 들어오면 대장이 바뀜(불안정). 직원이 지정/변경할 방법 없음.
- 결제: 결제 데스크(단체 일괄)가 있으나 "남은 전액"만 / 기간·방별 배분 없음 / 몇 박 냈는지 표시 없음.
  - 지금 클릭 수(69만원 3박): 방 선택 1 → 결제 2 → 단체 일괄 3 → 금액 직접 입력(69만) 4 → 수단 5 → 확인 6 (+ 입력). 어느 방에 몇 박이 반영됐는지는 안 보임.

## 2. 데이터
- 새 결제 테이블 없음. 방(예약)별 `booking_payments` 한 줄씩 bulk insert (한 번에 = 같은 created_at → 묶음 취소).
  - 기존 열 `night_date`(첫 박) 사용 + 새 열 `period_nights`. note = "기간결제 10/27~10/29 3박".
- 박별 금액: `night_rates`(박별 요금) 있으면 그대로, 없으면 판매가를 균등분할(나머지는 마지막 박). 추가금(판매가 − 박별합)·환불은 마지막 박에서 가감해 합이 항상 "받을 돈(revenueOf)"과 같게.
- 박별 결제 상태(순수 함수, shared/periodPay.ts): 기간 표시가 있는 결제는 그 박들을 채우고, 넘치거나 기간 없는 결제는 맨 앞 미결제 박부터 채움(FIFO). 기존 결제·장부 합계는 안 바뀜.
- 단체 일괄 수납(group_id 결제)은 합계엔 포함, 방별 기간엔 미반영(안내 문구).
- 대장: `booking_groups.lead_booking_id`(nullable, FK set null). 없으면 자동: 투숙 중(퇴실·중도퇴실 안 한) 방 우선 → 수납 많은 순 → 목록 순.
  - 기간 결제 저장 시 자동 대장이 흔들리지 않게 현재 대장을 고정 저장.

## 3. UI
- 단체 뱃지 클릭(1) → "단체 기간 결제" 시트: 3박 × 3객실 = 690,000원 미리 채워짐 → [카드로 690,000원 결제](2). 방 선택 → 패널 [기간 결제]로도 진입.
- 시트: 기간 칩(1/3/7박/잔여전체/직접), 수단 칩(카드/현금/이체), 방별 줄(방·박당 요금·이번 금액·"N박 결제 완료 · 이후 미결제"), 단체 합계(받은 돈·받을 돈), 다음 기간 합계, 금액 수정, 대장 지정(방 선택), 뱃지 색.
- 키보드: 1/3/7 숫자 칩, Enter 확인, Esc 닫기 (수단 단축키는 만들지 않음). 390px: 바텀시트, 칩 44px.
- 기간 시작은 기본 "오늘"(밀린 박이 없으면 첫 미결제 박). 오늘 전에 미결제 박이 있으면 "밀린 것부터 / 오늘부터" 칩으로 고른다 — 기본은 오늘부터(퇴실한 방의 옛 미수가 3박 결제를 끌고 가지 않게).

## 4. 엣지
- 중도퇴실: 퇴실 이후 박은 없어짐, 받을 돈은 revenueOf(환불 반영). 초과 수납은 "초과 X원" 표시.
- 방 이동: 결제는 예약 기준이라 방이 바뀌어도 유지. 라벨은 현재 방.
- 취소/노쇼 방 제외. 박별 요금 미정(0)이면 시트에서 막고 "요금 먼저".
- 후불/입금확인: 기존 payState·결제 줄과 같은 테이블 → 그대로 반영. 환불은 기존 환불 흐름.
- 총액 수정 시 최대잔여법으로 방별 배분(합 = 입력 금액).
- 결제 유료 게이팅 OFF 유지.
