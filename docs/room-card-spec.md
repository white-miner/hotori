# HOTORI 현황 객실카드 사양

기준: 2026-10-29 사용자 주석 10개와 최종 4:5 요약/상세 합의. 이전 상세 카드의 가변 높이·최소 510px 규칙은 폐기한다. 기존 현황 경로와 예약·업무 명령은 유지한다.

## 배치·비율·가독성

- 기존 `#/board/now`, 건물·층·객실 실제 순서 유지. 건물 최다 객실 수를 열 수로 사용하여 1실 층도 같은 카드 폭.
- 카드 전체(하단 버튼 포함) `aspect-ratio: 4 / 5`. FHD 1920×1080, 레일 사이드바에서 약 171.5×214.4px. 실제 59객실/8층 모두 한 줄씩, 층 가로 넘침 없음.
- 카드 최소 폭 168px. 사이드바 고정·작은 데스크톱에서는 한 층을 한 줄로 유지하고 층별 가로 스크롤 허용. 글자 축소 금지. 모바일에서는 열 수 축소.
- 객실번호 26px, 이름·총액 18px, 본문 16px, 상태 15px, 하단 버튼 16px/42px. 요약의 긴 이름·타입·단체명은 말줄임과 전체 툴팁/상세창 제공. 금액은 자르거나 반올림하지 않는다.
- 층 이름 22px/굵게, 앞에 저장된 층 컬러 막대, 객실 수 16px. 층마다 전체 너비 실선.
- 상단 공실번호 나열 제거. 미니맵·점유 집계·타입 재고 유지. 상단 패널은 현황에서 스크롤되도록 하여 카드를 덮지 않는다.

## 요약 카드

`src/NowRoomCard.tsx`, 기존 `Dashboard.nowCell`의 Booking과 roomCardModel을 사용.

- 상단: 흰색 객실번호 + 기존 점유 상태. 번호 배경만 흰색 대비 4.5:1 이상이 되도록 같은 계열의 진한 색으로 보정. 저장 색과 상태 색은 변경하지 않는다.
- 보조: 실제 객실 타입·예약 경로, 예약자명(대표객실은 단체명·대표).
- 기간: 숙박은 날짜 범위와 박수, 열린 숙박은 퇴실 미정, 대실은 실제 시각 범위. 전체 입퇴실 연도·날짜·시간은 툴팁/상세창.
- 금액: Booking.price 예약 총액과 결제 요약. 고액의 정확한 숫자 표시를 위해 결제 요약은 메타 행으로 이동하고 예약 경로는 상세창에서 확인.
- 단체: 기존 UUID 기반 G 표시번호·색·순번, 왕관+대표 또는 단체명+연결 아이콘. 전체 대표객실 번호/단체명은 상세창·툴팁.
- 단체가 없으면 빈 단체 영역을 만들지 않는다. 빈 객실은 예약 없음/판매 상태만 표시하고 임의 손님·금액을 만들지 않는다.
- 상세보기 안내 점은 예약 안내·홀드·이동·특이사항 등의 존재를 표시한다. 청소 제외·주차·턴오버·병행 대실 등 원래 안내와 업무 연결은 전체 상세창에서 유지.
- 하단 두 버튼: 상세보기/빠른 업무. 빠른 업무는 기존 좌측 사이드바 reveal과 실제 선택을 사용.

## 전체 상세창

- 읽기 전용 객실 요약 모달. 실제 타입·예약자·경로·입퇴실 연도/날짜/예정 시간·이용 기간·예약 총액·실제 박당 요금·결제 수단/금액·미수·회사·메모·특이사항·단체 연결 정보를 표시.
- 박당 요금은 기존 nowNightRate/장기 요금표만 사용. 총액 균등분할 금지.
- 시간은 호텔 설정과 earlyIn/lateOut 및 자정 경계를 반영. 실제 처리 시각으로 위장하지 않는다.
- 예약 상세·수정 → 기존 onOpen, 빠른 업무 → 기존 사이드바. 점유 밤 달력·특이사항·다른 예약 진입점 유지.
- Esc/바깥 클릭/닫기, 키보드 초점 순환·복귀. 실시간 재렌더가 작성/조작 중 초점을 빼앗지 않도록 모달 수명 동안 초점 관리.
- 공유에서는 금액·예약 메모·객실 특이사항을 숨기고 변경 버튼 비활성화.

## 상태·설정·임시 예약

- 투숙 중 빨강, 대실 파랑, 판매가능 초록, 퇴실예정 앰버. 입실예정/판매중지는 중립색 예외.
- 기존 nowFlags의 퇴실 예정 시각 6시간 전 규칙과 늦은 퇴실·열린 숙박 규칙 유지. 오늘 퇴실 가능한 예약의 퇴실예정 클릭 → 기존 퇴실 확인 모달. 임의 날짜/읽기 전용에서는 실제 처리하지 않는다.
- 청소 데이터와 점유는 독립 유지.
- 현황의 층 색 선택기는 제거. 기존 설정 → 객실 배치 → 층 이름 → 호실 번호 색상으로 통일. 기존 호텔 설정 저장/구독 사용.
- 상단 전체/임시만 필터 제거. 임시 예약이 있거나 필터가 활성일 때 좌측 업무 패널에서 확인·필터·확정 가능.

## 관리기록

- 상단 확인 필요 버튼을 관리기록으로 변경. 기존 자동 경고 배지는 확인사항 건수임을 접근성 이름에 명시.
- 전용 모달: 기록 목록/확인사항 탭. 기록 검색·전체/미해결/해결 필터·새 기록·객실 연결·해결/다시 열기.
- 기존 room_memos의 kind=delivery(인수인계)와 useRoomMemos save/setStatus/실시간 구독 재사용. 호텔 공용(roomId=null) 허용, 기존 120자 제한 유지. 별도 테이블/마이그레이션 없음.
- 기존 인수인계 기록도 같은 목록에 표시. 해결된 과거 기록을 기본 목록에 보존한다. 자동 탐지한 확인사항은 기존 TangleInbox를 내장하여 고치기/이대로 둠/복원 동작 유지.
- 읽기 실패를 빈 목록으로 위장하지 않는다. 저장 실패 시 입력을 보존하고 재시도 가능. 작성/해결은 기존 DB 결과를 받은 후 목록에 반영.

## 단체 연결·제약

- 기존 bookings.groupId, booking_groups 및 groupify/moveBookingGroup/setGroupLead/saveGroupInfo 재사용. 대표객실은 관리 포인터이며 예약의 단독 소유자가 아니다. 객실별 예약·입퇴실·결제 보존.
- G 표시번호와 구성원 표시 순서는 기존 도입된 호텔별 기기 localStorage 레지스트리. 서버 공통 표시번호/순서 동기화는 이번 범위에 추가하지 않았다.
- 실제 구성은 본관 40실+별관 19실=59실. 41실 예시를 맞추기 위해 실제 데이터를 조작하지 않는다.
