# HOTORI 현황 객실카드 사양

기준일: 2026-10-29. 최신 원격 main `4f4ec23`의 좌측 사이드바·현황/배치 통합 구조 위에서 기존 `Dashboard.nowCell`을 교체한다. 예전 카드의 슬롯 순서·278px 고정 높이는 새 현황 카드에 적용하지 않는다. 기존 `RoomCardFacts`와 금액 계산 함수는 다른 소비자를 위해 유지한다.

## 화면과 배치

- 기존 `#/board/now`를 사용한다. 별도 현황판은 만들지 않는다. `#/board/rooms`의 기존 리다이렉트도 유지한다.
- PC에서는 건물/층의 기존 정렬과 `floor.rooms` 순서를 유지하면서 층당 한 줄로 표시한다. 건물의 최다 객실 수를 열 수로 사용하여 1실 층도 같은 카드 폭을 유지한다.
- 1920×1080에서 사이드바 레일과 고정 상태를 검증했다. 본문 16px, 예약자/금액 18px, 호수 26px, 상태 15px, 버튼 최소 높이 42px.
- 1350px 이하 데스크톱에서는 작은 글자로 줄이지 않고 층별 가로 스크롤을 허용한다. 모바일 전용 디자인은 이번 우선 범위가 아니다.
- 카드 높이는 내용에 따라 늘어난다. 카드 안에서 내용을 잘라 넣지 않으며, 페이지 세로 스크롤을 허용한다.

## 카드

`src/NowRoomCard.tsx`가 실제 Booking과 기존 `roomCardModel`을 받아 표시한다.

- 머리: 층 색상 배경의 객실번호, 실제 객실 타입, 주요 상태.
- 단체: G 표시번호, 단체명, 순번/총 구성원 수, 왕관+대표 또는 대표객실 연결.
- 예약 상세: 예약자, 예약 경로, 입실 날짜·시간, 퇴실 날짜·시간, 이용 형태·박수, 객실 요금, 결제 상태.
- 가격은 `Booking.price`를 **예약 총액**으로 명시한다. 박당 가격은 기존 `nowNightRate`/장기 요금표 결과만 별도로 표시한다. 총액을 박수로 나눈 추정값은 만들지 않는다.
- 입퇴실 시간은 숙박의 경우 `settings.stayTimes`와 `earlyIn`/`lateOut`을 반영한 예정 시간이다. 실제 처리 시각을 생성하지 않는다. 자정 경계는 날짜에도 반영한다. 대실은 실제 `startTime`/`endTime`을 사용한다.
- 빈 객실은 예약 없음과 빈 항목을 표시한다. 취소/노쇼는 기존 예약의 상세 진입점과 별도 안내를 유지한다.
- 하단 상세보기는 기존 `onOpen` 예약 수정 화면을 연다. 빈 객실은 객실 운영 화면을 연다. 빠른 업무는 기존 선택 상태를 설정하고 좌측 사이드바를 펼친다.
- 이용 기간 팝오버, 특이사항, 배정 체크, 드래그 이동 타깃, 이동 예약·턴오버·판매 타입 안내, 주차 표시는 유지한다. 숙박과 대실이 같은 객실에 있으면 별도 예약 진입점을 제공한다.
- 공유 화면에서는 금액을 숨기고 변경 버튼을 비활성화한다.

## 상태와 청소

- 투숙 중: 빨강. 대실: 파랑. 판매가능: 초록. 퇴실예정: 앰버.
- 미입실 예약은 입실예정, 임시 마감은 판매중지로 구분하여 판매가능으로 오인하지 않게 한다.
- 퇴실예정은 기존 `nowFlags`와 체크아웃 예정 시각 6시간 전 윈도우를 그대로 사용한다. 늦은 퇴실을 반영하며 열린 숙박의 보호 구간 종료를 퇴실예정으로 표시하지 않는다.
- `noClean`은 청소 제외 안내로 유지한다. 청소 데이터나 점유 규칙을 삭제/수정하지 않는다.

## 층 색상

- 기존 `HotelSettings.floors[].color`를 사용한다. 객실 개별 색 데이터는 보존한다. 이 현황 카드의 번호 배경에는 층 색상을 적용한다.
- 팔레트/직접 색상/색상 코드로 미리보기하고 저장한다. 같은 층의 모든 번호에 즉시 반영된다.
- 저장 전 기존 `fetchFreshAround`로 최신 설정을 읽고 해당 층 색만 변경한 뒤 기존 `saveHotel`로 저장한다. 실패는 설정 팝업에서 표시한다.
- 번호 글자색은 기존 대비 계산 `textOn`으로 흰색 또는 진한 글자를 선택한다. 상태 색과 단체 색은 별도 CSS 영역이다.

## 단체 연결과 저장

- 정식 단체 식별자는 기존 `bookings.group_id` / `booking_groups.id` UUID다. 각 객실의 Booking은 독립적으로 요금·객실·기간·입퇴실·결제를 소유한다.
- 대표는 기존 `lead_booking_id`와 `groupLeadOf`의 업무 규칙을 사용한다. 화면 순번 정렬을 대표 자동 선택에 사용하지 않는다.
- 색은 기존 `badge_color`의 g1~g6 팔레트를 사용한다.
- 관리 UI는 기존 `groupify`, `moveBookingGroup`, `setGroupLead`, `saveGroupInfo`, 단체 상세/추가/결제 화면을 재사용한다.
- 개별 연결 해제는 해당 예약의 group_id/group_name만 바꾸는 기존 명령을 사용한다. 전체 해제는 같은 명령을 구성원별로 호출한다. 중간 실패 시 이미 성공한 결과를 되돌려 덮지 않고 오류를 알려준다.
- 단체로 받은 결제는 원래 단체 정산 내역에 남는다. 해제된 개인 예약으로 금액을 임의 분배하거나 대표객실에 이전하지 않는다.
- G 표시번호와 구성원 표시 순서는 `hotori.roomCards.groups.<hotelId>`의 기기별 localStorage에 저장한다. 표시 순서는 객실번호나 대표객실에서 유도하지 않는다. 실제 연결은 항상 UUID로 수행한다.
- 표시번호·순번을 모든 직원/기기에 동일하게 공유하는 서버 저장은 이번에 추가하지 않았다. 그런 공통 번호가 필요하면 별도 스키마/권한/동시성 설계를 먼저 승인받아야 한다. DB 스키마/마이그레이션은 변경하지 않았다.
