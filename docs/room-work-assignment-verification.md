# 객실 업무·과거 현황·배정 모드 검증

검증일: 2026-10-30 (KST). 기준: main 34c318c, 실제 데이터 59실(본관 40 / 별관 19).

## 변경

- 과거 날짜의 활성 이용 카드는 `이용완료`로 표시한다. 실제 체크아웃 기록을 생성하지 않으며 상태 창에서 예약의 현재 실제 상태를 따로 확인한다. 예약이 없었던 과거 날짜는 `이용 기록 없음`으로 표시한다.
- 미배정 예약의 방배정을 시작하면 전용 카드로 전환한다. 이전 손님·금액 대신 예약 전체 기간의 배정 가능 여부와 다른 타입 여부를 표시한다. 기존 배정 검증, 다른 타입 확인, 완료 기록 보존 절차를 재사용한다.
- 빠른 업무는 전용 모달로 열린다. 숙박/대실 판매, 이 객실에 미배정 예약 배정, 선택한 예약의 박별 약정 및 수납 기록, 이용상태 변경 입구를 제공한다.
- 상태 칩은 상태 변경 탭으로 연결한다. 기존 입실, 퇴실 확인, 대실 종료, 중도퇴실 잔액 처리 및 되돌리기 흐름을 재사용한다.
- 대체 객실 수량은 자동 재조회로 초기화하지 않는다. 날짜/대상 타입을 바꾸거나 창을 새로 열면 저장값을 읽는다. 편집 도중 여유 재고가 줄어도 입력 항목을 유지하고 저장 시 최신 여유로 검증한다.
- DB 모델, 마이그레이션, 예약/수납 데이터의 일괄 정정은 없다.

## 제한 및 보존 규칙

- 과거 `이용완료`는 그 날짜의 이용 기록 표시이며 실제 퇴실 처리를 뜻하지 않는다.
- 중도퇴실은 기존 2박 이상/입실 다음 날~예정 퇴실 전날 규칙 및 과거 정정 검증을 유지한다. 1박/입실 당일 변경은 예약 수정 입구를 사용한다.
- 박별 약정이 없는 기존 예약은 금액을 임의 배분하지 않고 `약정 미등록`으로 표시한다.
- 선택 예약의 수납과 단체 공통 수납을 구분한다. 다른 단체 객실의 개별 수납은 이 예약 기록에 섞지 않는다. 공통 수납을 방별로 임의 배분하지 않는다.
- 기존 결제 조건·예정일·예약의 반복 정산 설정을 표시한다. 저장된 반복 주기가 없으면 미설정으로 표시한다.
- 실제 운영 예약의 체크인/체크아웃/배정/수납 저장은 검증 목적으로 실행하지 않았다. 해당 데이터 변형은 단위 테스트와 격리 검증으로 확인했다.
