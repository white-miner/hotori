# 기존 단체 일정·요금 수정 / 카드 청구 근거 검증 (2026-10-30)

## 결과 및 입구
- 현황 객실카드의 단체 라벨 → ‘단체·대표객실 관리’ → ‘일정·요금 수정’.
- 빠른 업무의 단체 패널 → ‘날짜별 객실·요금 수정’.
- 단체 결제 등록창, 장부의 단체 행·정산창에서도 같은 수정창을 연다.
- 객실번호·타입·이름 → 객실 상세. 날짜는 기존 상세 말풍선. 요금·결제는 단체 근거창(개인은 객실 상세). 카드 박별 요금 → 전체 약정·수정 입구.

## 저장과 보존
`Booking`의 기존 날짜·박별 요금 모델과 `updated_at`을 재사용한다. 스키마/DB 마이그레이션 없음.

수정한 예약의 `nights`, `price`, `price_unset`, `night_rates`, `open_ended`, `room_segments`만 UPDATE한다. 예약 ID·체크인·호실 ID·단체 ID·이름·연락처·실제 입퇴실·수납 테이블은 쓰지 않는다. 이동 구간은 줄인 기간에 맞춰 자르고, 늘린 기간은 기존 마지막 호실에 붙인다. 결제 금액을 새 청구에 맞춰 재분배하거나 삭제하지 않는다.

같은 타입이어도 실제 퇴실할 호실을 사용자가 고른다. 날짜별 실 수와 약정 합계·호텔 잔여를 함께 표시한다. 다른 예약과 연장 호실이 겹치면 표시·확인한다. 이미 실제 퇴실했거나 취소·노쇼·장기 원장인 예약은 이 창에서 재개하지 않는다.

전체 변경 전 서버 값을 조회하고 각 UPDATE에 기존 `updated_at`·호텔·단체·활성 상태 조건을 건다. 다른 직원의 수정을 덮어쓰지 않는다. DB 전체 트랜잭션은 새로 만들지 않았다. 중간 실패 시 확정 저장한 객실 수를 표시하고 이후 쓰기를 중단한다. 성공한 객실은 편집 대상에서 빼고 미저장 객실만 재시도한다. 응답 유실은 한 번 재조회해 반영 여부를 확인한다.

## 요금 원칙
- 새로 늘어난 밤은 금액이 비어 있으면 저장할 수 없다. 기존 박 요금은 날짜별로 보존한다.
- 기존 박별 약정이 없으면 총액·타입 요금으로 추측하지 않는다. 해당 객실의 모든 박 요금을 직접 입력하고 총액 변경에 동의해야 한다.
- 기존 박별 금액이 모두 있으면 총액과 박별 합의 가산·할인 차액은 유지한다. 박당 추가 항목은 새 박수에 맞춘다. 기존 환불액보다 새 총액이 작아지는 경우는 기록 정정으로 안내한다.
- 예약이 바뀌어도 수납은 그대로이므로 미수/초과 수납만 다시 계산한다. 실제 체크아웃·환불은 별도 업무다.

## 연장 0원 경로 개선
숙박 판매의 +1박 칩과 ‘오늘까지 즉시 연장’, 장부의 단가 자동 일괄 연장을 제거/대체했다. 단체는 날짜별 편집, 개별 1박 연장은 날짜·약정 요금·결제 방법을 확인하는 모달을 이용한다. 기본 후불이며 실제 수납 시 카드·현금·이체를 선택한다. 0원은 ‘서비스’를 명시한 경우만 허용한다. 예전 예약 수정의 연장 패널도 입력 누락을 차단한다.

`applyExtend`는 기존 박별 표가 없더라도 이번에 입력한 날짜/요금을 반드시 기록한다. 과거 요금은 채우지 않는다. 이미 체크아웃한 예약의 재연장도 차단했다.

## 단체·대표객실 / 금액 근거
연결 객실과 상태·타입·박별 약정·객실별 실제 수납을 한 모달에서 확인하고 대표객실을 변경할 수 있다. 대표 지정은 기존 `lead_booking_id`만 바꾸며 예약·결제 소유자를 바꾸지 않는다. 현황 강조·객실 업무·객실 추가·결제 등록·일정 수정·결제 기록 정정으로 연결한다.

초과 수납·미수금·청구·결제와 객실 소계/요금에 hover 시 계산 내역을 표시하고 클릭 시 근거창을 연다. 청구는 객실별 날짜·저장 단가·장부 반영액·추가 항목·환불과 비교할 수 있고, 수납은 날짜·카드/현금/이체·대상·금액·메모를 표시한다. 원인이 기록돼 있지 않으면 원인을 단정하지 않고 현재 계산식과 최근 변경 기록을 제공한다. 미래 예정 청구와 현재 미수는 구분한다.

객실카드는 빨간 미수금과 실제 저장된 박별 약정 요금을 표시한다. 미등록 박은 0원으로 대신하지 않는다. 단체 미수는 ‘단체 미수’로 명시하며 각 방에 임의 배분하지 않는다. 모든 요금·수납 정보는 공유 화면에서 계속 숨긴다. 추가 정보의 가독성을 위해 카드 최소 폭은 264px, 4:5 비율(264×330)과 층별 한 줄/가로 스크롤은 유지한다.

## 확인한 UI / 자동 검증
- 기존 배정 단체의 실제 카드 → 관리 모달 → 일정 수정, 개별 빠른 업무 → 1박 연장 모달 → 취소 후 기존 4박 유지 확인. 운영 예약/결제는 쓰지 않았다.
- 격리 화면은 실제 `GroupScheduleSheet`, `GroupEvidenceSheet`, `ExtendNightModal`, `ConfirmHost`를 사용하며 저장 어댑터만 메모리로 분리했다.
- 기존 목/금 각각 6실(총90만원)에서 스탠다드·욕조 각1실만 금요일 퇴실로 변경 저장 → 6실/4실, 10객실박, 총73만원. 실제 호실과 예약 ID 및 기존 결제54만원 유지.
- 연장 금액 누락 저장 차단 → 새 날짜 금액 입력 후 반영. 두 번째 예약 저장 실패를 주입 → 1/2 저장 확인 → 남은 1실만 재시도. 첫 성공 예약 재저장 없음.
- 대표 변경 후 청구·수납 불변. 0원 유료 연장 차단, 후불 9만원은 새 밤 요금9만원/실제 수납0원으로 구성됨을 확인.
- 전체 테스트 834개 통과(새 11개 포함). TypeScript·Vite·서버 빌드 확인. 기존 큰 JS 청크 경고는 남아 있다.

## 제한
운영 DB에 테스트용 수정·결제를 실행하지 않았다. 격리 저장과 실제 운영 UI 입구/취소를 검증했으며, 운영 예약의 약정 미등록 금액은 임의 정정하지 않았다. 기간 단축은 예정 퇴실 변경이며 실제 체크아웃이 아니다. 장기 원장·완료된 실제 퇴실 기록은 기존 전용 화면에서 정정한다.
