# 호토리 로컬 초안 실행 안내

2026-10-17 · v0.1 개발 초안

## 바로 확인

개발 서버: http://127.0.0.1:5173

API: http://127.0.0.1:3100/api/health

이 초안은 **이 PC에서만 실행하는 단일 호텔 체험**입니다. 실제 호텔·고객·직원 정보는 입력하지 마세요. 가상 호텔 16실과 예약 12건으로 시작하며, 화면의 플랜 전환은 결제 없는 데모입니다. 계정 인증, 직원별 접근 제한, 다른 기기 공유, 유료 결제와 앱스토어 출시는 아직 구현하지 않았습니다.

## 실행 명령

Node.js와 npm 설치 환경에서 프로젝트 폴더를 열고 다음을 실행합니다.

```powershell
npm install
npm run dev
```

브라우저에서 http://127.0.0.1:5173 을 엽니다. 종료는 실행 중인 터미널에서 Ctrl+C입니다. API와 웹 개발 서버는 127.0.0.1에만 연결되며 외부 네트워크에 공개하지 않습니다. 3100·5173 포트를 다른 프로그램이 사용하면 해당 프로그램을 먼저 종료해야 합니다.

빌드한 결과를 한 서버로 확인하려면 개발 서버를 종료한 후 실행합니다.

```powershell
npm run build
npm start
```

이때 브라우저 주소는 http://127.0.0.1:3100 입니다. 개발 서버와 빌드 서버를 동시에 실행하지 않습니다. DB 이중 접근 방지를 위해 서버 프로세스 잠금 파일을 사용합니다.

```powershell
npm test
```

마지막 객실 동시 판매, 예약 변경 실패 롤백, 중복 요청, 날짜 경계, 수수료 반올림, 플랜 제한, 인수인계 항목, 객실 준비 상태, 실제 DB 재시작 지속성을 검사합니다.

## 데이터 저장

- 서버의 내장 PostgreSQL(PGlite)에 저장하며 경로는 `.hotori-data/postgres`입니다.
- 브라우저의 localStorage가 원본 저장소가 아닙니다. 새로고침과 서버 재시작 후에도 저장된 데이터가 유지됩니다.
- 가상 데이터는 DB가 처음 생성될 때 한 번만 입력합니다. 날짜가 바뀌어도 기존 예약을 자동으로 덮어쓰지 않습니다.
- `.hotori-data`는 Git에서 제외했습니다. 이 폴더를 지우면 입력한 데모 데이터가 사라집니다. DB 실행 중 파일을 직접 수정하거나 삭제하지 마세요.
- 현재 폴더의 한 PostgreSQL JSONB 레코드가 호텔 업무 상태를 보관합니다. 상용 다중 호텔 스키마, 자동 백업·복구와 보관·삭제 정책은 후속 개발입니다.

## 구현한 서버 업무

- 확정 예약 등록·전체 변경·취소, 타입별 숙박일 재고 검증.
- 실제 객실 배정·입실·예정일 퇴실. 청소 필요 객실, 시설 점검/판매 중지 객실의 입실 차단. 퇴실 시 청소 필요 전환.
- 객실 등록과 청소·시설 상태 변경. 현재·미래 예약 수용량을 훼손하는 판매 중지는 명시적으로 거절.
- 객실별 인수인계 항목 접수·처리·해결·재열기. 해결 기록 보존.
- 가상 구성원 등록과 서버 시각 기준 출퇴근 기록.
- 호텔 이름 설정과 결제 없는 무료/프로 체험 전환.
- 숙박일 기준 일별 리포트와 프로 기간 리포트. 금액은 원 단위 정수, 예약별 수수료율 스냅샷, 일별 수수료 합계가 예약 수수료와 일치하도록 누적 반올림 차이로 배분.
- 변경 버전 비교와 감사 이력. 같은 요청 키·내용을 재전송하면 같은 결과를 반환하며 다른 내용은 거절.

읽기·쓰기 모두 서버 큐로 직렬화합니다. 재고·한도 검사, 업무 변경, 감사 로그와 요청 결과는 한 PostgreSQL 트랜잭션에서 커밋됩니다. 오류 시 기존 기록을 보존합니다. 이는 현재 단일 서버의 안전 장치이며 분산 서버의 동시성 보장이 아닙니다.

## 적용한 체험 플랜

무료: 과거·미래 각 1개월, 20실, 기존 건물동 1개, 객실별 미해결 항목 1개, 하루 리포트. 프로: 과거·미래 각 6개월, 객실·동 상품 수량 제한 없음, 객실별 미해결 항목 30개, 기간 리포트, 신규 출근 기록.

달력 월 기준으로 월말은 해당 월 마지막 날로 보정합니다. 미래 상한일 체크아웃은 허용하고 상한일 숙박은 허용하지 않습니다. 과거 기간 밖 데이터는 지우지 않으며 일반 예약 응답·연결 감사 이력에서 제외합니다. 경계에 걸친 예약은 허용된 숙박일과 금액만 표시하고 전체 내용 변경은 거절합니다.

프로에서 무료로 바꿔도 기존 미래 예약과 인수인계·근무 이력은 유지합니다. 기존 근무의 퇴근과 기존 예약 입퇴실·취소·재배정은 처리할 수 있습니다. 단, 무료로 전환한 호텔이 20실을 초과하면 신규 판매를 보류합니다. 최대 20실의 무료 판매 객실 선택 화면은 아직 없어 프로 체험으로 전환해 검토해야 합니다. 실제 상품 정책의 최종 확정과 결제 권한 검증은 별도입니다.

## 초안의 한계와 다음 개발

현재 예약은 같은 타입·동일 요금으로 예약한 객실 수량 단위입니다. 객실별 부분 취소, 객실 이동, 숙박 중 타입 변경, 조기 퇴실·요금 재계산, 고객 수납·환불과 OTA 정산은 후속입니다. 일일 판매액은 숙박일 객실 매출이며 실제 입금액이나 순이익이 아닙니다. 채널·수수료 설정 편집은 아직 없고 예시 채널의 고정 요율을 예약 시점에 저장합니다.

현재 시설의 판매 중지는 모든 향후 숙박일에 적용합니다. 기간별 판매 중지와 긴급 고장 수용 부족 예외 처리는 후속입니다. 기존 예약과 충돌하면 변경을 거절하므로 긴급 예외를 기록해 자동 재배정하는 완성된 흐름은 아닙니다. 연박은 이동 없이 배정 가능성을 보수적으로 검사하며 가능한 배정도 기존 배정의 재조정 없이는 거절될 수 있습니다.

조직 등록은 실제 계정 생성·초대가 아닙니다. 모든 요청은 로컬 데모 운영자가 처리합니다. 근태 정정 승인, 역할별 조회 제한, 다중 호텔 데이터 분리, 결제 제공자 연결과 구독 검증이 있어야 실제 호텔 서비스를 운영할 수 있습니다.

화면은 반응형 웹 초안입니다. Android·iOS 설치형 앱 빌드·서명·실기기 검수·스토어 배포, PWA 설치·오프라인 지원은 완료된 것으로 취급하지 않습니다. 현재 localhost 제약 때문에 다른 휴대폰에서 접속해 공동 사용하지 않습니다.

## API 계약

- `GET /api/state?date=YYYY-MM-DD`: 호텔, 허용 범위, 재고, 예약, 객실, 항목, 구성원, 근무, 감사 이력.
- `GET /api/reports?start=YYYY-MM-DD&end=YYYY-MM-DD`: 종료일 포함, 무료는 하루만 허용.
- `POST /api/commands`: JSON `{type,data,requestId}`. 요청 식별자는 8~100자의 영문·숫자·대시·밑줄입니다.
- 오류: HTTP 오류 상태와 `{error,code}`. 변경 성공: `{message,id,revision}`.

타입 계약은 `shared/types.ts`, 검증은 `server/domain.ts`, PostgreSQL 트랜잭션과 멱등은 `server/store.ts`, 로컬 HTTP 경계는 `server/index.ts`에 있습니다. 명령은 reservation.create/update/cancel/assign/checkin/checkout, room.create/update, issue.create/update, property.update, member.create, attendance.clockin/clockout, demo.plan입니다.

서버는 허용된 127.0.0.1 호스트와 Origin, JSON 변경 요청을 검사하며 wildcard CORS를 열지 않습니다. 이는 로컬 데모 경계이며 사용자 인증을 대신하지 않습니다.
