# 객실카드 인원·결제·단체 표식 정리

2026-10-30 KST. 사용자 주석 1~4, 6~7 구현. 주석 5의 박당 요금은 아래 기획안까지이며 요금 계산/저장 변경은 하지 않았다.

## 변경 파일

- `src/NowRoomCard.tsx`: 인원 버튼/조회, 정확한 플랫폼 경로와 실제 수납수단, 이름 위 단체 고정 슬롯, 상세 인원/결제수단 추가.
- `shared/detailedRoomCard.ts`: 실제 결제 기록의 수단을 집계하며 단체 공통 수납 범위를 명시.
- `src/Dashboard.tsx`: 실제 객실 타입 전달, 인원 클릭을 기존 예약 수정으로 연결.
- `src/App.tsx`: 인원 항목 바로 열기 요청을 기존 Entry에 전달.
- `src/Entry.tsx`: 인원 항목 펼침/포커스, 저장 인원이 없을 때 보는 객실 타입의 기본 인원 사용. 기존 인원 추가금/판매금/저장 규칙 재사용.
- `src/styles.css`: 예약자와 예약 없음 모두 28px, 단체가 없을 때도 이름 위 빈 줄 유지, 수납수단 한 줄 확보.
- `src/detailedRoomCard.test.tsx`: 빈 단체 슬롯·라벨 순서·OTA 경로·수단/단체 범위·인원 우선순위·고액/공유 회귀 확인.

저장된 인원이 있으면 그 값이 우선하며, 없을 때만 실제 객실 타입의 기본값을 표시한다. 공실은 기본 인원을 조회하며 예약 인원을 임의로 생성하지 않는다. 결제 기록이 없으면 수단을 추정하지 않고 수납 기록 없음을 표시한다. OTA는 야놀자/아고다/에어비앤비 등 실제 경로를 사용한다. 단체 공통 기록은 단체 카드·이체와 같이 표시하고 객실 총액을 개별 수납액으로 오인시키지 않는다.

## 박당 요금 표시 제안 — 아직 구현하지 않음

우선순위는 객실 자체에 저장된 날짜별 계약 요금이다. 같은 타입이라도 다른 객실의 단가나 단체 총액을 복사/균등 배분하지 않는다. 요금표가 없으면 요금 미입력과 기존 박별 요금 입력 입구를 제공한다. 호텔 타입 요금은 제안으로 구분하고 계약값처럼 표시하지 않는다. 명시적인 0원과 미입력을 구분한다.

권장 표시안:

1. 하단 요금 영역에 보는 날짜, 평일/주말 구분, 그 객실의 실제 당일 박당 요금 한 줄을 고정한다. 달력 날짜 이동 시 그 날짜 값으로 갱신한다. 퇴실일에는 기존 업무 규칙에 따라 마지막 숙박일임을 날짜와 함께 표시한다.
2. 넓은 카드에서는 저장된 평일·주말 계약 단가를 보조 줄에 표시한다. 같은 평일/주말 안에서도 날짜별 계약 단가가 다르면 변동이라고 쓰고 범위를 보여 주며, 클릭하면 실제 날짜별 금액을 펼친다.
3. 상세에는 기존 박별 요금표와 연결하여 모든 날짜의 확정 금액, 추가 인원/이불 등 객실별 추가 항목, 총액과의 차이를 확인한다. 장기 숙박은 기존 요일별 요금/원장 기준을 별도로 따른다.
4. 금·토를 하드코딩하지 않고 호텔 주말 요일·특별일 설정을 따른다. 시즌/특별일의 타입 제안과 실제 저장 계약 단가를 혼동하지 않는다.

공간 조건: 모바일 예시의 약 311×389px 카드에는 아래 여백이 충분하지만, FHD에서 10객실 한 줄을 유지하면 약 171.5×214.4px다. 이 크기에서 기존 총액·결제수단과 박당 요금 여러 줄을 모두 상시 표시할 여유는 없다. 권장은 작은 카드의 주 금액을 당일 박당 요금으로 바꾸고 예약 총액/평일·주말 전체표는 상세로 옮기는 방식이다. 총액도 계속 상시 표시하려면 카드 비율/한 층 표시 폭을 함께 재검토해야 한다. 이 표시 선택은 사용자가 기획을 검토한 뒤 확정한다.
