# 객실 카드에 "하루 요금" 대신 "총액"이 보이던 원인 보고서

작성: 2026-10-28 (Asia/Seoul) · 기준 커밋: `1411a87`(수정 전) → 이 문서와 같이 들어가는 수정 커밋

## 한 줄 요약
객실 카드(현황·배치)는 **"하루 객실 요금"을 한 번도 계산한 적이 없습니다.** 카드에 찍히던 금액은 전부 **그 객실의 총액/잔금/최근 결제액**이었고, 그걸 계산하는 함수(`nowAmountGlance`)는 처음부터 "금액 한 줄"만 돌려주도록 만들어져 있었습니다. 요구하신 "하루 요금(₩70,000)"은 카드 입장에서 **존재하지 않는 값**이었습니다.

## 1. 코드가 실제로 하던 일 (수정 전)

| 보드 | 위치 | 하던 일 |
|---|---|---|
| 현황 | `src/Dashboard.tsx` nowCell, `nowAmountGlance(b, plat, groupCtx)` 호출 (~3426) → `nowamt` 블록 | 함수가 준 문자열 한 줄을 그대로 출력 |
| 현황 | `src/Dashboard.tsx` ~3430 `payMethod` | 결제수단을 금액 앞에 접두어로만 붙임 (`nowPayMethodPrefix`, `shared/nowboard.ts:530`) |
| 배치 | `src/Dashboard.tsx` roomCell ~2121 | `won(b.price)` 또는 `잔금 ₩…` 을 직접 출력 (booking.price = 전체 숙박 합계) |
| 계산 | `shared/nowboard.ts:489-518` `nowAmountGlance` | 아래 표 참고 |

`nowAmountGlance`가 돌려주던 값:
- 개별 예약, 잔금이 남음 → `잔금 ₩(남은 돈)` (`nowboard.ts:507`)
- 개별 예약, 완납 → **마지막 결제액** `₩…` (`nowboard.ts:508-512`) 없으면 `₩b.price`(총액)
- 단체 객실 → `stayNightAmounts(b)`의 **합계** (`nowboard.ts:499-502`)
- 장기 숙박 → `미수 ₩…`
- OTA → `₩b.price`(총액)

어느 갈래도 "1박 요금"이 아닙니다.

## 2. 요구사항과 달랐던 이유
요구: 객실번호 / 이용기간(10/25~10/27) / 결제수단+금액(이체690,000) / 투숙객 / 회사명 / **₩하루 요금**.

1. **하루 요금 자체가 없음.** 박별 요금표(`booking.nightRates.nights[날짜]`, `shared/nightrates.ts`)는 이미 저장돼 있는데 카드는 읽지 않았습니다.
2. **합계로 합쳐 버림.** `stayNightAmounts`(`shared/periodPay.ts:47-65`)는 박별 요금에 추가요금·부가요금을 **마지막 박에 몰아 얹은** 값입니다. 청구/수납 계산용이라 "하루 요금"으로 쓰면 마지막 날만 비정상적으로 큽니다. 단체 카드가 이 값의 합계를 보여 줘서 총액처럼 보였습니다.
3. **결제수단·금액이 분리돼 있음.** 금액은 잔금/최근 결제 중 하나, 수단은 별도 접두어라 "이체690,000"처럼 *그 방 결제의 수단+금액*이 아니라 *잔금 상태에 따라 바뀌는 숫자*였습니다.
4. **이용기간이 점유 밤 라벨 하나뿐.** `nowNightRange`(`nowboard.ts:421`)가 "10/25~27"식으로 줄여서 "10/25~10/27" 형식이 아니었습니다.
5. **회사명 필드가 카드에 연결 안 됨.** 회사명은 단체의 `payerCompany`(`shared/settle.ts` `GroupInfo`)에만 있는데 카드에서 읽지 않았습니다.
6. **대표객실 표기가 "대장"**이라 용어가 달랐고, 호수 팝오버(`GroupRoomNoHit`, `src/ui.tsx:263-330`)는 있었지만 "대장" 글씨만 있었습니다.

## 3. 이전 수정이 놓친 이유
- `98ac546`("객실 카드 자기 요금")은 단체 객실이 **단체 전체 금액을 되풀이**하던 문제만 고쳤습니다. 그 결과 "그 객실 자기 숙박 합계"가 나오게 됐을 뿐, 여전히 **합계**였습니다. 문제를 "누구의 돈이냐(단체 vs 객실)"로 봤고 "단위가 무엇이냐(박 vs 전체)"는 보지 않았습니다.
- 테스트(`shared/nowboard.test.ts`)도 "합계가 맞는가"를 확인했지 "하루 요금이 맞는가"는 없었습니다. 그래서 초록불인데 화면은 요구와 달랐습니다.
- 박별 요금표 작업(`groupRates`, `nightrates`)은 입력/저장 쪽만 만들고 **보드 카드 표시는 건드리지 않았습니다**.

## 4. 수정 내용
- **새 계산 모듈 `shared/nowCard.ts`** (테스트 `shared/nowCard.test.ts`)
  - `nowNightRate(b, 날짜)`: 박별 요금표의 **보는 날짜 칸**. 기간 안에서 요금이 다르면 `varies=true`(변동). 박별 표가 없으면 1박 요금, 그것도 없으면 (총액−추가요금−부가요금)÷박수를 **"추정"**으로 표시. 총액을 그대로 쓰지 않습니다.
  - `nowLongStayRate`: 장기숙박 요금표(고정/요일별)에서 해당 날짜 요금.
  - `nowRangeFull`: `10/25~10/27`, 1박은 `10/25`, 퇴실 미정은 `10/25~`.
  - `nowPayParts`/`nowPayText`: 결제를 수단별로 합쳐 `이체690,000`, 여러 수단은 `이체690,000 · 카드100,000`(최대 2개, 나머지 `외 N건`). **그 객실 자기 결제만**, 대표객실은 단체 결제를 함께.
  - `nowCompanyOf`: 단체 `payerCompany`.
- **새 컴포넌트 `src/RoomCardFacts.tsx`**: 회사 · `₩70,000`(+`변동`/`추정` 뱃지, 마우스 올리면 기간 최저~최고) · 결제수단+금액. 현황(nowCell)과 배치(roomCell) 둘 다 이 컴포넌트를 씀.
- **`src/Dashboard.tsx`**: 두 카드에서 총액/잔금 출력 제거, 위 값들로 교체. 날짜 라벨은 `nowRangeFull`. 대표객실 칸 호수 옆에 `대표객실` 뱃지(누르거나 올리면 연결 객실 호수 팝오버, 기존 `GroupRoomNoHit` 재사용).
- **용어**: 화면의 "대장" → "대표객실" (`shared/group.ts` 칩 라벨, `src/ui.tsx` 팝오버, 단체 화면들). 테스트 기대값 갱신.
- 미결제 방은 `미결제`(붉은 톤), OTA/미정 금액은 `금액미정`. 단체 비대표 방은 자기 결제만 보이고 단체 결제는 대표객실에만 보입니다.

## 5. 남은 한계 (솔직하게)
- **회사명은 단체에만 있음.** 개별 예약에는 회사명 필드가 없어 카드에 안 나옵니다(만들어서 채우지 않았습니다). 필요하면 예약에 "회사명" 입력칸을 추가하는 후속 작업이 필요합니다.
- 박별 요금표가 없는 옛 예약은 "추정" 뱃지로 평균을 보여 줍니다(정확한 하루 요금이 아님을 표시).
- 602호 단체 데이터는 건드리지 않았습니다.

## 6. 추가 확정 사항 (11:23 KST 지시 반영)
- 단체의 **모든 객실 카드**: 그 객실 자기 하루 요금(예: 602 ₩70,000 / 501·301 ₩80,000)을 항상 표시.
- **대표객실 카드**: 이용기간 + 박수(`10/25~10/27 · 3박`) + 단체 결제(`이체690,000`)를 추가로 표시 → 690,000이 그 기간의 결제임이 보임.
- **그 외 구성원 카드**: 이용기간 + 자기 하루 요금만. 결제 금액은 표시하지 않음.
- 카드를 선택하면 열리는 상세/수정은 기존 그대로.
